# PRINCE2 7 comparison · Realtime Quiz hybrid governance

| # | Hybrid element (this project) | PRINCE2 7 equivalent | Main difference |
|---|-------------------------------|----------------------|-----------------|
| 1 | Sponsor (Head of IT) | Project board with the executive | PRINCE2 has a board with three roles, here one person decides |
| 2 | Project manager (lecturer, outside Scrum) | Project manager | Same role: plans stages, reports and escalates; here the PM does not manage the team's daily work |
| 3 | Product owner (Student A) | Senior user (on the project board) | PRINCE2 separates user and delivery interests; here the PO sits inside the team |
| 4 | Scrum master (Student B) | Team manager | Facilitates and protects the process instead of directing work packages |
| 5 | Sprint (14 days) | Work package inside a management stage | A sprint has a goal, not an agreed product description with tolerance |
| 6 | Phase between gates (W1-3, W4-7, W8-11, W12-14) | Management stage | Same idea: control point at the end of each stage |
| 7 | Gate G1-G4 | End stage assessment (and project initiation approval for G1) | PRINCE2 requires an end stage report and a next stage plan |
| 8 | Product backlog item | Product description | An item has acceptance criteria only, no full description with quality method |
| 9 | Definition of done | Quality criteria and acceptance criteria | One generic checklist instead of criteria per product |
| 10 | Weekly highlight report | Highlight report | Same purpose; here fixed to Friday and one page |
| 11 | Tolerance breach and exception report | Exception report and exception plan | PRINCE2 also asks for an exception plan after the board decision |
| 12 | Sprint review and retrospective | Product review / lessons log update | Review is a demo; lessons are captured at sprint rhythm, not in a log |
| 13 | Closure criteria and G4 | Closing a project (end project report, benefits review plan) | PRINCE2 adds a follow-on actions recommendation and a benefits review |
| 14 | Risk register with scores | Risk register and risk management approach | Same register; the risk appetite is not stated formally here |

## What PRINCE2 would add that this governance lacks
PRINCE2 would require a business case and a project brief that tie the quiz tool to a benefit for the IT department (for example, less manual quiz marking time), and it would review that benefit after the pilot; our governance only checks that the pilot works. It would also give the sponsor a board with an explicit senior user and senior supplier, so the product owner's priorities and the lecturer's quality demands are balanced by a third party instead of one decision maker, and it would force change and issue registers, which our four-student team currently handles through the backlog and the weekly report.

## What PRINCE2 would make heavier
For four students with 560 hours, PRINCE2 would add product descriptions for every deliverable, a stage plan and end stage report at each of the four gates, a project board meeting for each exception and a separate configuration management and quality management approach. Writing and reviewing these documents could use more than the 56 h reserve, take hours away from the roughly 25-30 points per sprint of development and slow the two-week feedback loop that the uncertain WebSocket technology needs.
